## Maintainer-only tooling (`scripts/`)

Not part of the installed `codecompass` package — each script's own module docstring says so explicitly.

- **`scripts/check_knowledge_base.py`** — a mechanical sanity check over CodeCompass's own `planning/knowledge/<slug>/` tree: required fields per record kind, cross-reference resolution, the Claim/Decision `supersedes` cross-kind hard rule, requirement-cites-approved-decision, anchor integrity, snapshot historical-integrity/completeness/current-divergence, and (Phase 82) `status: verified` citing a real, passing oracle result for every required check of its own contract — including (`decisions/0082`, corrective pass) failing closed when a required scope's only evidence is a historically recorded `PASS` that cannot currently be reconfirmed against the real implementation (`--ledgerkit-root PATH`, default `~/projects/ledgerkit`), and (`decisions/0083`, second corrective pass) failing closed — a blocking finding, not merely informational — when `codecompass`'s own oracle/knowledge_intermediate modules cannot be imported at all, so a broken environment can never report this check as silently skipped. Report-only by default; `--strict` exits non-zero on a blocking finding. Hard-coded to this one repository — not something an adopting project can simply point elsewhere (see `docs/concepts/knowledge-model.md`).
- **`scripts/check_user_docs.py`** — a mechanical sanity check that this repository's own narrative docs match its own code (CLI command coverage, `ANTHROPIC_API_KEY` mention, `VendorConfig` field coverage, internal link resolution, retired-identifier-as-live-prose detection, generated-artifact-vs-generator drift, and several project-process-specific checks). Report-only by default; `--strict` exits non-zero on a blocking finding.
- **`scripts/check_contracts.py`** (Phase 82) — a mechanical sanity check over `planning/contracts/<slug>/` oracle-contract/oracle-result files: schema shape, cross-reference resolution (`contract_id`/`check_id`), tamper-evidence (content-digest recomputation against a live Ledgerkit-style checkout when available), the computed PASS/FAIL/GAP/INVALID aggregate per check, and source-citation depth (a cited symbol must actually exist at the cited location, not merely a resolvable file path). Since `decisions/0082` (corrective pass), `--strict` also fails closed — not merely informationally — when a required check's only on-record evidence is a historically recorded `PASS` and the Ledgerkit checkout is unavailable to reconfirm it; since `decisions/0083` (second corrective pass), `--strict` also fails closed when `codecompass.oracle` itself cannot be imported, since every check in this script depends on it. Since `decisions/0088` (Phase 83, found by directly extending a real contract for the first time), a result whose own recorded hash/digest no longer matches current reality is downgraded from blocking to informational specifically when a *different*, current `PASS` already exists for the same `check_id` — a superseded historical result, not a live problem; stays blocking, unchanged, when no current `PASS` exists for that check at all. Report-only by default; `--strict` exits non-zero on a blocking finding.
- **`scripts/run_balance_from_spec_oracle.py`** (Phase 82) — executes Phase 82's one real oracle contract (`planning/contracts/balance-from-spec/`) against a real Ledgerkit checkout and writes one new, permanent `<check_id>--<run_id>.yaml`/`.txt` result/raw-output file pair per execution (`decisions/0082`, corrective pass) — never overwriting a prior run's own evidence. An execution whose check reference resolves to only skipped tests is recorded `INVALID`, never `PASS` (`decisions/0083`). `--check-id` (repeatable, Phase 83) runs only the named check(s) — e.g. re-running a contract's pre-existing checks after extending it with a new one that has no real test to exercise yet. Not a shipped `codecompass` command.
- **`scripts/assess_change_impact.py`** (Phase 83, corrected `decisions/0089`) — evidence-backed change-impact assessment against a target checkout's own real behaviour, reusing `oracle.py`/`knowledge_intermediate.py` unmodified. Given `--target-repo-root`, `--target-graph-db` (defaults to `<target-repo-root>/context-graph.db` — the target's own graph, never CodeCompass's self-referential one), `--knowledge-root` (defaults to this checkout — where canonical knowledge/contracts actually live, never assumed to be under the target repository), `--slug`, and one or more `--changed path:start-end` ranges: resolves each range against **every** indexed first-party symbol whose own span intersects it (not only the one enclosing the range's start) only when the target graph's own `source_files.content_hash` for that file matches the live content (otherwise `stale_index`, never a best-effort guess against possibly-shifted line numbers) and both `start` and `end` lie within the file's own extent; a range only partly covered by indexed symbols is reported `partially_resolved`, naming the unmapped line(s) explicitly rather than discarding them. Each resolved symbol is classified independently as `no_recorded_relationship` (no Evidence cites it — never read as "safe"), `relevant_no_coverage_link` (a *path-and-symbol*-matching Evidence cites it, but no Claim bridges it to a check-resolving test-evidence that itself parses as a real, correctly-scoped `OracleResult` for the live contract), or `behavioural_risk` (a Claim bridges both) — purely from existing Evidence/Claim citation chains, never from `test_input_paths`, file proximity, or a same-named symbol in a different file. With `--run-checks`, each `behavioural_risk` check is freshly re-executed exactly once per range (deduplicated across symbols that share it, with every contributing symbol still named) and classified `CONFIRMED_REGRESSION` (a fresh `FAIL`) / `INVALID_ASSESSMENT` (a fresh `INVALID` — reachable independently of the aggregate state, `decisions/0087`) / `VERIFIED_SCOPE` (a fresh `PASS`) / `VERIFICATION_GAP` (no fresh result attempted at all) — determined solely by the one fresh result, a historical `PASS` on file never masking it. No new graph table, no call-graph, no `git diff` parser. Not a shipped `codecompass` command (`planning/phase-83-semantic-change-assurance.md`).
- **`scripts/prepare_cleanroom_branch.py`** — builds and validates an explicitly allow-listed export of this repository's own source/tests/configuration, for a documentation-reconstruction exercise of the kind that produced this very `docs/` tree. Ordinary repository-maintenance tooling, not a runtime capability of the `codecompass` product. See [`clean-room-redocumentation.md`](clean-room-redocumentation.md) for the full, proven process this and the related `cleanroom_broker*`/`cleanroom_prompt_assembler.py` scripts implement.
