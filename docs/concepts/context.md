# Concept: "context" — an overloaded word, by design

"Context" has no single canonical meaning in CodeCompass's own vocabulary. Evidence gathered from the project's own domain-knowledge research names at least five genuinely distinct, related-but-not-interchangeable senses. This page documents all five rather than silently picking one, because conflating them is a real, named source of confusion in the project's own history.

1. **`context-graph.db`** — the deterministic SQLite persistence layer of vendors, symbols, and edges. See `docs/architecture/data-and-control-flow.md`.
2. **"The context CodeCompass supplies to an agent"**, generally — an informal umbrella term covering everything a consuming agent might read: digests, graph query output, generated Skills, `/discovery`, chat answers. Not one artifact; a description of the whole output surface.
3. **A "context packet"** — a narrowly-scoped, curated Markdown artifact CodeCompass's own development process produces internally (under `planning/knowledge/<feature-slug>/context-packet.md`), citing every substantive assertion back to a formal knowledge-record id (see `docs/concepts/knowledge-model.md`). This is part of how CodeCompass's own maintainers document a specific feature's own design rationale — not something end-user `codecompass` commands generate for *your* project's dependencies. Mechanically and purposively distinct from a digest (sense 5 below): a digest is generated unconditionally on every sync for every tracked vendor; a context packet is generated once, gated on a human/lead review step, for one CodeCompass feature at a time.
4. **Context-quality assessment instruments** — named artifacts (`context-health.md`, `context-use-log.md`, a `context-quality-evaluation.md` report) that CodeCompass's own project history uses to evaluate how well sense 2 is working in practice. Distinct from sense 2 itself — these are *about* it, not instances of it.
5. **A plain-English usage inside unrelated internal role names** — e.g. a role named something like "roadmap-context-curator" in the project's own internal process vocabulary, where "context" means ordinary planning-document state, not runtime context at all.

If you see "context" used informally in CodeCompass documentation or source comments, check which of these five senses is actually meant before assuming it refers to `context-graph.db` specifically.
