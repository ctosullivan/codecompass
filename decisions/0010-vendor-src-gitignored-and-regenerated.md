# 0010. `vendor/<name>/src/` snapshots are gitignored and regenerated, not committed

## Status

Accepted

## Context

[`decisions/0004`](0004-vendor-src-snapshot-not-node-modules-reference.md)
established that `FULL`-depth vendors get a copied source snapshot at
`vendor/<name>/src/` rather than a reference into `node_modules` (or the
equivalent installed location for other ecosystems), but left open whether
that copy is committed to git or gitignored and regenerated on `sync`.
Phase 0's `.gitignore` already excludes `vendor/` by default, but the
original spec (§6) explicitly deferred the final decision to the Phase 1
plan.

## Decision

`vendor/<name>/src/` snapshots stay gitignored (the existing `vendor/`
entry from Phase 0 already covers this) and are regenerated by `sync`
from the ecosystem adapter's `source_location`, not committed to git.

## Alternatives considered

- **Commit snapshots to git.** Rejected — repo size grows with every
  `FULL` vendor's full source tree, and every dependency version bump
  produces a large, noisy diff unrelated to the consuming project's own
  changes. A fresh clone needing to run `depcompass sync` once before
  standalone mode works for `FULL` vendors is an acceptable cost:
  deterministic tree generation (`FILETREE.md`/`DEPTREE.md`) already
  requires at least one `sync` run to produce any per-vendor output at
  all, so this doesn't introduce a new category of "must run a command
  first" friction — it's consistent with output that was already
  generated, not hand-maintained.

## Consequences

- A fresh clone (or CI checkout) has no working standalone-mode chat for
  `FULL` vendors until `depcompass sync` has been run at least once.
  Onboarding documentation added in Phase 4+ should call this out.
- Phase 4's `sync` implementation must handle both the first-run case
  (`vendor/<name>/src/` doesn't exist yet) and the repeat-run case
  (regenerating over an existing snapshot) — noted here for that phase's
  plan file, not itself a Phase 1 scope item.
- This closes the open question referenced in `architecture/overview.md`'s
  Known footguns section as of Phase 0.
