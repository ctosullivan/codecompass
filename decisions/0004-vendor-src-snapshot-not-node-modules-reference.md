# 0004. FULL vendors get a copied source snapshot, not a node_modules reference

## Status

Accepted

## Context

Standalone consumption mode (`cd vendor/<name> && claude`) needs a stable
source tree to point a Claude Code session at for `FULL`-depth vendors.
The obvious shortcut — pointing at the dependency's actual installed
location (`node_modules/<name>`, a Python site-packages path, a Cargo
registry cache entry) — is tempting because it avoids duplicating files on
disk.

## Decision

`FULL` vendors get a **copied** pinned source snapshot at
`vendor/<name>/src/`, generated at `sync` time. Standalone mode never
references the package manager's installed location directly.

## Alternatives considered

- **Live reference/symlink into the installed location** (`node_modules/`,
  site-packages, Cargo registry cache). Rejected — package managers prune,
  dedupe, and reinstall these directories routinely (a plain `npm install`
  can rewrite `node_modules` contents). A digest whose pinned-source
  backing can silently change or disappear the next time someone installs
  dependencies is not a stable target for later reference, and would
  produce confusing "the file changed but the digest didn't" bugs.

## Consequences

- `vendor/<name>/src/` duplicates on-disk content that already exists
  elsewhere in the installed dependency tree, for every `FULL` vendor.
- Whether these snapshots are committed to git or gitignored and
  regenerated by `sync` is a separate, still-open question — see
  `planning/CONTEXT.md` and the Phase 1 plan file, which is where §6 of
  the original project spec designates that it should be resolved.
- Because the snapshot is a copy, it stays byte-stable across
  `npm install`/`pip install`/`cargo build` runs elsewhere in the project,
  which is exactly the property standalone mode depends on.
